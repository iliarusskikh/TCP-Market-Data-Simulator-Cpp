Binary Protocol { TICK + HEARTBEAT }

Fixed-size packed messages on a TCP byte stream. All wire layout lives in protocol.hpp; the client consumes the feed via recv_feed, the server enqueues via ClientSession::enqueue_*.

01

Why binary

Market-data feeds on the wire are binary: fixed offsets, known sizes, no parsing overhead.

  • Parsing cost — binary copies bytes into a struct after endian fixups; no token scanning or string-to-float conversion per tick.
  • Structure — fields have fixed offsets and types. Size is known at compile time (static_assert in protocol.hpp).
  • Framing on TCP — the hard part is not the struct layout but accumulating full messages on a byte stream (partial reads).
Decision

Binary over text — two fixed message types only (TICK, HEARTBEAT). Rejected: line-delimited text, JSON, or length-prefixed variable payloads (unnecessary for this scope).

02

Fixed-size vs length-prefixed

SchemeIdeaTrade-off
Fixed-size Every message of a type is exactly sizeof(T) bytes Simple read loop; no variable payload; size changes only when you change the struct
Length-prefixed Header with length (or type+length), then N payload bytes Needed for strings / variable books; more framing states
Decision

Fixed-size for both TICK (25 bytes) and HEARTBEAT (9 bytes). Discriminate with a leading uint8_t msg_type. Rejected: length-prefixed framing — no variable payloads in this protocol.

03

#pragma pack / alignment

Compilers insert padding so members land on natural alignments (e.g. uint32_t on a 4-byte boundary). Padding makes sizeof larger and layout compiler-dependent — bad on the wire.

protocol.hpp
#pragma pack(push, 1)   // no padding between members
struct TickMsg { /* ... */ };
struct HeartbeatMsg { /* ... */ };
#pragma pack(pop)       // restore previous packing

static_assert(sizeof(TickMsg) == 25, "TickMsg must be packed to 25 bytes");
static_assert(sizeof(HeartbeatMsg) == 9, "HeartbeatMsg must be packed to 9 bytes");

Packed structs are for serialization. Convert field-by-field with hton*/ntoh* via tick_to_wire / tick_from_wire — never memcpy a host-endian struct straight to the socket.

04

Endianness

Network byte order is big-endian. Apple Silicon and x86 hosts are little-endian — multi-byte integers must be converted on send and receive.

WidthHost → networkNetwork → host
16-bithtonsntohs
32-bithtonlntohl
64-bithost_to_net64net_to_host64

uint8_t msg_type needs no swap. protocol.hpp provides custom 64-bit helpers (portable; avoids relying on htobe64 availability).

Pitfall

Skipping ntoh* on receive “works” only if both ends are the same endianness. The wire helpers always convert — that is the correct habit.

05

Partial reads — TCP is a stream

TCP delivers a byte stream, not messages. One send of 25 bytes can arrive as two recvs of 10 and 15 — or one recv that contains two full messages plus a fragment.

protocol.hpp — recv_exact
// Loops until n bytes or error/close.
// Handles EINTR; caller handles EAGAIN when non-blocking.
IoStatus recv_exact(int fd, void* buf, size_t n);

// recv_feed: read msg_type byte, then remainder for that type
IoStatus recv_feed(int fd, FeedEvent& ev);

Always accumulate until you have a full message. Never assume one recv equals one message.

06

Message structs

protocol.hpp
enum class MsgType : uint8_t { TICK = 1, HEARTBEAT = 2 };

#pragma pack(push, 1)
struct TickMsg {
    uint8_t  msg_type;      // MsgType::TICK
    uint32_t symbol_id;
    int64_t  price;         // scaled integer (micros: 1e6 == 1.0)
    uint64_t timestamp_ns;
    uint32_t volume;
};
struct HeartbeatMsg {
    uint8_t  msg_type;      // MsgType::HEARTBEAT
    uint64_t timestamp_ns;
};
#pragma pack(pop)

// sizeof(TickMsg) == 25
// sizeof(HeartbeatMsg) == 9

Serialize: host-order struct → tick_to_wire / heartbeat_to_wire → send_exact. Deserialize: recv_feed → tick_from_wire / heartbeat_from_wire.

07

Runtime paths

PathWhereRole
recv_feed src/client.cpp Read one framed message; populate FeedEvent (tick or heartbeat)
ClientSession::enqueue_tick / enqueue_heartbeat client_session.hpp Convert to wire bytes, append to outbound queue
send_tick / recv_tick protocol.hpp Typed helpers for tests / simple blocking demos — not the main server/client loop

recv_feed reads the first byte to discriminate type, then reads the remaining sizeof(msg) - 1 bytes — so partial reads never desync the stream.

08

Project decision

Decision

Fixed-size packed binary with two message types only: TICK and HEARTBEAT. Prices are scaled integers on the wire. All multi-byte fields use network byte order; receivers loop until a full message is buffered. Rejected: ORDER/ACK, length-prefixed blobs, JSON.

09

Common pitfalls

✕

Forgetting ntoh* on receive

Prices, IDs, and timestamps look “almost right” on little-endian hosts talking to themselves — then break on a different machine.

✕

Assuming one recv = one message

TCP is a stream. Partial and coalesced reads are normal; without recv_exact / recv_feed, you desync and every later message is garbage.

✕

Sending without packing

Default alignment padding means sizeof and field offsets disagree between compilers. Use #pragma pack(push, 1) and verify with static_assert.
