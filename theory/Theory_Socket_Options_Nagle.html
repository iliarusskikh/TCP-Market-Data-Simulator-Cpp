Socket Options { Nagle & TCP_NODELAY }

Small TICK and HEARTBEAT messages need low send latency. set_tcp_nodelay in socket_opts.hpp disables Nagle on every data-carrying socket — distinct from SO_REUSEADDR on the listener.

01

Nagle's algorithm

Nagle coalesces small TCP writes: if unacknowledged data is already in flight, the stack holds a new tiny send until an ACK arrives or enough bytes accumulate to fill a segment. That cuts packet count for bulk or chatty byte streams.

For a market-data feed of fixed-size ticks (25 bytes) and heartbeats (9 bytes), coalescing adds delay. Each message is small and latency-sensitive — waiting to batch hurts more than it helps.

02

TCP_NODELAY

TCP_NODELAY = 1 disables Nagle. Set it with setsockopt at level IPPROTO_TCP (not SOL_SOCKET):

  • Level: IPPROTO_TCP
  • Option: TCP_NODELAY
  • Value: int opt = 1

Needs <netinet/tcp.h> for the option name on POSIX.

03

Where we set it

set_tcp_nodelay runs on every connected socket that carries application data:

  • Server — each fd returned by accept(), in src/server.cpp, before the fd moves into a ClientSession
  • Client — the connect socket after successful connect(), in src/client.cpp
Decision

NODELAY on data sockets only. Not on the listening socket — listeners do not send ticks. Rejected: setting NODELAY only on the listener (accepted fds do not reliably inherit it on all platforms).

04

SO_REUSEADDR

The server sets SO_REUSEADDR on the listen socket so a restart can re-bind while a previous incarnation sits in TIME_WAIT.

OptionProblem it solvesWhere
SO_REUSEADDRBind / restart vs TIME_WAITListen socket (src/server.cpp)
TCP_NODELAYSmall-message send latencyAccepted + client connect fds (socket_opts.hpp)

Same API family (setsockopt), different problems. Do not conflate them.

05

Buffer sizes

SO_RCVBUF / SO_SNDBUF tune kernel socket buffer sizes. They exist and matter at scale; for this simulator we leave OS defaults.

Decision

Leave buffer sizes at defaults. Rejected: tuning SO_RCVBUF/SO_SNDBUF — unnecessary for the client counts and message rates this project targets.

06

Project decision

Decision

Enable TCP_NODELAY on every data-carrying connection via set_tcp_nodelay in socket_opts.hpp. Leave send/receive buffer sizes at OS defaults. Keep SO_REUSEADDR on the listen socket only.

07

Code snippet

socket_opts.hpp
#include <netinet/tcp.h>   // TCP_NODELAY
#include <sys/socket.h>

inline bool set_tcp_nodelay(int fd) {
    int opt = 1;
    if (setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt)) < 0) {
        return false;  // log warning; connection still usable with Nagle on
    }
    return true;
}

// server: after accept → set_tcp_nodelay(csock.get())
// client: after connect  → set_tcp_nodelay(sock.get())
08

Pitfalls

✕

Setting NODELAY only on the listen socket

Accepted fds do not reliably inherit TCP_NODELAY from the listener on all platforms. Set it on each accepted connection and on the client's connect socket.

✕

Wrong setsockopt level

TCP_NODELAY is IPPROTO_TCP, not SOL_SOCKET. Wrong level → silent failure or EINVAL.

✕

Treating SO_REUSEADDR as a latency knob

It only helps bind after restart. It does nothing for tick send latency.
