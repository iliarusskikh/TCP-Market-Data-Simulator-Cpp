C++ { Code reference }

Language features and library pieces that actually appear in this tree — with the file that demonstrates each one. Companion to the systems notes (sockets, poll, protocol), not a general C++ tutorial.

01

Scope & dialect

ItemIn this project
StandardC++11 (CMakeLists.txt: CMAKE_CXX_STANDARD 11)
DepsPOSIX sockets + C++ standard library only — no Boost, fmt, Asio, …
Build shapeTwo executables (server, client); logic in header-only helpers under include/
ConcurrencySingle-threaded event loops; no std::thread workers (client only uses this_thread::sleep_for for backoff)
Decision

C++11 floor. Enough for enum class, move semantics, chrono, mt19937, and range-for. Rejected: C++17 structured bindings / std::optional — would raise the bar without changing the story.

03

Types & enums

enum class (scoped enums)

TypeFileRole
MsgTypeprotocol.hppWire discriminator (: uint8_t underlying type)
IoStatusprotocol.hppOk / Closed / Error
FeedKindprotocol.hppResult of recv_feed
LogLevellog.hppInfo / Warn / Error
ConnStateclient.cppDisconnected → Connecting → Connected

Scoped enums do not promote to int silently — wire code uses static_cast<uint8_t>(MsgType::TICK).

struct vs class

  • Aggregate / POD-ish data: TickMsg, HeartbeatMsg, AppConfig, FeedEvent, ClientSession — public members by default via struct.
  • Encapsulation / invariants: SocketGuard, TickGenerator, LatencyStats, LogStream — class with private state.

Fixed-width integers

<cstdint>: uint8_t, uint32_t, uint64_t, int64_t on the wire and in config symbol IDs. Avoids “how wide is long?” portability issues.

Nested types

TickGenerator::SymbolState is a private nested struct — implementation detail of the generator.

04

Layout, packing & casts

ConceptWhereNotes
#pragma pack(push, 1) / pop protocol.hpp No padding between wire fields — layout matches the documented 25 / 9 byte sizes
static_assert protocol.hpp Compile-time check: sizeof(TickMsg) == 25, etc.
std::memcpy type-pun host_to_net_i64 Safe bit-preserving int64 ↔ uint64 for endian swap (avoids undefined aliasing)
reinterpret_cast recv_feed, enqueue, bind/connect Bytes ↔ struct; sockaddr_in* ↔ sockaddr*
static_cast Everywhere Narrowing / enum → integer / duration counts — preferred over C casts
Value init T{} TickMsg wire{}, FeedEvent, … Zero members before filling
In-class initializers SocketGuard::fd_{-1}, AppConfig defaults Defaults without writing every ctor
Caveat

Packing + casting a buffer into a struct is intentional here for a fixed binary protocol. Do not treat this as a general pattern for arbitrary objects — alignment and strict aliasing still matter.

06

Templates

Only light template use — no custom containers or CRTP.

include/log.hpp
template <typename T>
LogStream& operator<<(const T& v) {
    ss_ << v;
    return *this;
}

That member template lets log_info() << "port=" << port accept any type streamable into ostringstream. STL templates used as clients: vector<T>, uniform_int_distribution<int>, duration_cast<nanoseconds>.

Container idioms

  • reserve before fill (TickGenerator, drop_dead)
  • emplace_back + std::move for new sessions
  • insert(end, p, p+n) to append wire bytes into out
  • swap to replace the clients vector after filtering dead ones
  • Range-for: for (auto& c : clients)

Exceptions (narrow)

load_config uses try / catch (...) around std::stoi / stoul. The I/O path is errno-based, not exception-driven.

08

chrono & clocks

ClockWhereWhy
steady_clock Server deadlines, client last_rx / inter-arrival, tick timestamp_ns Monotonic — safe for intervals and timeouts
system_clock log.hpp timestamps Human-readable wall time in log lines

Common pieces: time_point, duration, duration_cast<milliseconds|nanoseconds>, milliseconds{n}, using clock = steady_clock, using namespace std::chrono in small helpers.

Decision

Two clocks, clear roles. Control-loop timing never uses wall clock (NTP can jump). Log stamps never use steady (not calendar time). See also Latency.

11

Deliberately unused (here)

Useful to know what this project is not demonstrating:

  • std::unique_ptr / shared_ptr — fds via SocketGuard; no heap graph of sessions
  • std::mutex, atomics (beyond sig_atomic_t), lock-free queues
  • virtual / inheritance / CRTP
  • std::function, callbacks as first-class design
  • C++17+: optional, string_view, structured bindings, if constexpr
  • Exceptions for control flow on the hot path

Those show up in other portfolio pieces; this one stays close to sockets + RAII + poll.
