Sockets { TCP & Berkeley API }

TCP is the transport for this market-data feed. The Berkeley socket API in src/server.cpp and src/client.cpp owns connection lifecycle — listen, accept, connect, send, close — with SocketGuard wrapping every fd.

01

TCP vs UDP

Both sit on IP. The difference that matters for this project is delivery semantics:

TCP (SOCK_STREAM)UDP (SOCK_DGRAM)
ConnectionYes — handshake, then a sessionNo — fire datagrams
ReliabilityRetransmits; in-order deliveryBest-effort; can drop / reorder
BoundariesByte stream (no message edges)Datagram = one message
Typical feed useRecovery channels, session-oriented feedsMulticast market data (A/B feeds)
Decision

TCP for this simulator — reliable, ordered delivery so the project focuses on framing, binary layout, poll(), and reconnect without also inventing loss recovery. UDP/multicast is a different project.

03

Byte Stream — No Message Boundaries

TCP delivers an ordered stream of bytes. One send() on the peer is not one recv() on yours. The kernel may coalesce or split writes arbitrarily.

  • A binary market-data protocol cannot rely on “one recv per send.” You need framing — knowing where a message starts and ends.
  • This project uses fixed-size messages (TICK / HEARTBEAT): loop until the full struct is read. See Binary Protocol and recv_feed in protocol.hpp.
Pitfall

“I sent one struct, so one recv gets one struct” is false on TCP. Always plan for partial reads (and partial writes on the send side).

04

SO_REUSEADDR and TIME_WAIT

After close(), a TCP endpoint can linger in TIME_WAIT so delayed packets from the old connection don't confuse a new one. That can hold the local IP:port for tens of seconds — restarting the server then fails with “Address already in use.”

SO_REUSEADDR (set on the listen socket before bind in src/server.cpp) lets the listening socket bind again while a prior instance's sockets are still in TIME_WAIT.

src/server.cpp
int opt = 1;
setsockopt(listen_sock.get(), SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
// then bind(listen_sock.get(), ...)

Different problem from TCP_NODELAY (Nagle / latency) — see Socket Options & Nagle.

05

htons and inet_pton

Network protocols use big-endian (“network byte order”). Hosts (Apple Silicon, x86) are usually little-endian — so ports and multi-byte integers need conversion helpers.

  • htons(port) — host to network short; used for sin_port on both server and client.
  • htonl / ntohs / ntohl — same idea for 32-bit fields; wire messages use these via tick_to_wire / tick_from_wire in protocol.hpp.
  • inet_pton(AF_INET, host, &addr.sin_addr) — presentation → network; used in src/client.cpp. Returns ≤ 0 on bad string.
src/client.cpp (pattern)
serv_addr.sin_family = AF_INET;
serv_addr.sin_port   = htons(static_cast<uint16_t>(cfg.port));
if (inet_pton(AF_INET, cfg.host.c_str(), &serv_addr.sin_addr) <= 0) {
    // invalid address string
}

Server uses INADDR_ANY (bind all interfaces) instead of a specific IP string — no inet_pton needed there.

06

Project Decision

Decision

TCP + Berkeley sockets for a session-oriented market-data feed: reliable ordered stream, fixed-size binary framing (protocol.hpp), non-blocking poll() on the server. Not UDP/multicast. Message types are TICK + HEARTBEAT only — no order flow.

Quick Reference & Pitfalls

CallRole
socketCreate fd (AF_INET + SOCK_STREAM = TCP)
bindServer: claim local IP:port
listenServer: mark passive; set backlog
acceptServer: new connected fd (non-blocking: loop until EAGAIN)

✕

Forgot close()

Leaks an fd. SocketGuard in socket_guard.hpp closes on scope exit — use it for listen, accept, and connect fds.

✕

Bind failed — port in use

Another process holds the port, or TIME_WAIT without SO_REUSEADDR. Check with lsof -i :port or change config.

✕

Connect failed

Server not running, wrong host/port, or firewall. Client retries with exponential backoff.

✕

Assuming message boundaries

One send ≠ one recv. Fixed-size framing via recv_exact / recv_feed is required.

✕

Skipping htons

Port bytes swapped on little-endian hosts → connect/bind to the wrong port.
